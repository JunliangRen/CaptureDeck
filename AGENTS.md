# CaptureRack agent memory

This is the repository handoff for coding agents. Start with the current Git status, the owning source, and [README.md](README.md). This file records architecture decisions and the last verified state. Update the relevant section when a change ships or its verification status changes.

## Working conventions

- Target .NET 11. The production Windows app uses native WinUI 3 and XAML. Uno Desktop is a separate QC prototype with its own build entry point.
- Save text files with CRLF in the working tree. Preserve existing package names, namespaces, CLI commands, and settings compatibility through directory moves. Tests live under `test/`.
- For commits, follow the user's Git identity using the repository-local author name and locally configured email. Keep GitHub usernames, machine-specific paths, private sample data, and credentials out of tracked files. Push or publish when the user requests it.

## Platform boundaries and sample flow

- Windows x64 is the currently supported live path for DeckLink and MSTape. The native App and Probe also build for Windows ARM64 and can run offline QC there. Check every hardware/backend combination separately before claiming ARM64 support.
- Uno runs the offline workflow on Windows and is packaged for macOS ARM64 through its own workflow. A macOS live source needs a native capture backend and device validation. MSTape, DirectShow COM, and WinUSB are Windows implementations.
- `ICaptureBackend` and `CaptureBackendRegistry` provide backend identity and lookup. The generic backend contract has typed requests, progress, and results. The native app currently resolves DeckLink directly and the FireWire CLI calls its MSTape implementation directly.
- `CaptureSampleHandler` delivers a `CaptureSample` synchronously. Its span borrows bytes from the source for the duration of that callback. Copy into owned storage before queueing or returning. The current contract carries optional stream-relative start and end timestamps and a discontinuity flag. The stream format is negotiated separately. False rejects delivery.
- `DirectShowSink` uses this contract. `TsRecording` copies accepted samples into pooled storage under a 64 MiB queue budget. Keep recording byte-preserving and report overrun explicitly. For future monitoring, bound its queue independently and signal sample gaps to a stateful decoder.
- `ITransportController` in `TransportControl.cs` models supported commands and observed state separately from host capture. An accepted command and an observed state change are distinct outcomes. Device control providers for AV/C, JLIP, and other RS-232 protocols are planned.

## Native WinUI and DeckLink

- Capture uses the Blackmagic SDK COM interfaces directly from managed code. A compatible Desktop Video driver/runtime is required for live capture. FFmpeg and FFprobe are used by offline MOV QC. The repo does not require a C++ build or an installed DeckLink SDK to compile.
- WinUI lets the operator choose the device, video input, audio input, input mode, media formats, and hardware analog input levels (Composite/S-Video 0.0/7.5 IRE setup, Component SMPTE/Betacam levels, Analog/XLR/RCA Pro/Consumer audio levels, and optional L/R hardware input gain scaling). Routing and analog overrides are applied for the session and restored when it stops. The DeckLink CLI probe uses the routing already configured in Desktop Video Setup.
- CaptureRack.App uses MicaAlt, a custom title bar with Capture / QC Center mode switching and an interactive multi-backend Source Rack switcher (`WorkspaceModuleRegistry` + `ICaptureWorkspaceModule` persisting `CaptureBackendId`), PerMonitorV2 DPI awareness (`app.manifest`), and System/Dark/Light studio themes (`Styles/StudioTheme.xaml`). `MainWindow` acts as a shell hosting three pluggable slots (`StageSlot`, `InspectorSlot`, `MonitorBarSlot`) plus `TransportControlSlot`; reusable views and controls live in `Controls/BroadcastMeterControl`, `Controls/PreviewMonitorOptionsBar`, `Controls/SplitResizeHandle` (native `SizeNorthSouth` resize cursor), `Controls/StudioBrushes`, `Views/DeckLinkInspectorView`, `Views/PlannedBackendStageView`, `Views/PlannedBackendInspectorView`, `Views/QcCenterView`, `Views/SettingsView`, and pure testable contracts in `Architecture/WorkspaceContracts.cs`. The monitoring stage defaults to Studio Split with a draggable split divider (`SplitPreviewRatio`, double-click reset), video preview above switchable Luma waveform / RGB Parade (`Code` / `IRE` scale) + Vectorscope/Spectrum/Events, a persistent ballistic stereo peak & phase meter with clickable L/R CLIP latch reset, and a collapsible/pinnable right inspector drawer (including an optional tape/reel filename label prefix and a reserved `TransportControlSlot` for future `ITransportController` UI). Preview-only display options (motion-adaptive Bob-Weave ×1 / ×2 or original preview, with progressive signals locked to original, display aspect override, BT.601/BT.709 matrix, safe-area & NTSC 480 crop guides, and non-blocking local speaker audio monitor) never alter recorded MOV video or PCM audio. Full-screen preview supports double-click, F11, Escape, hover/touch button fade, and an auto-hiding bottom mini control bar. The single-row bottom bar holds preview and crimson record buttons, Composition-animated recording indicators (rotating reel, top stream sweep, 3-bar tally activity, breathing border), backend-driven dynamic `TelemetryStrip` chips, storage capacity bar, inline QC status/cancel, and status flyout. All animations respect Windows `UISettings.AnimationsEnabled`.
- Settings are loaded from `%LOCALAPPDATA%\CaptureRack\settings.json`. Capture, analog level, preview-only monitor, tape label, split ratio, scope mode/scale, and control selections are stored with backwards-compatible defaults. Restore the last selections on launch and wait for the user to start preview. The settings page resolves the Windows display language on first launch or when migrating a legacy unset language, then persists one of English, Simplified Chinese, Traditional Chinese, and Japanese, alongside theme, default layout, preview defaults, and FFmpeg/FFprobe toolchain diagnostics. Keep the back header fixed and support Mouse Back and Alt+Left. Mouse wheel handling accepts `WM_MOUSEWHEEL`, `WM_POINTERWHEEL`, and a foreground-only raw mouse fallback across the Settings, QC Center, and right Inspector `ScrollView` panels while preserving open dropdowns and native scrolling.
- MOV recording starts from an active preview and an existing output directory. Auto detect requires a readable frame in the active preview mode before opening the writer. Readable no-input frames qualify and the UI labels the mode as a fallback. A detected mode change ends the current Auto clip before switching preview and is reported in QC. Names use local time, optional sanitized tape/reel label prefix (`RecordingFileNaming`), and format tokens, for example `CaptureRack_20261124_060236_633_10bit-Uncompressed_16bit-PCM.mov` or `Tape04_SideA_CaptureRack_20261124_060236_633_10bit-Uncompressed_16bit-PCM.mov`. Stopping recording finalizes the file and starts QC while preview continues. QC Center in CaptureRack.App supports both MOV QC and offline 188/192-byte MPEG-TS analysis (`TsFile.Analyze` + JSON export) with a session QC history sidebar (`QcSessionHistory`).
- The SDK supplies 10-bit `v210` or 8-bit UYVY video. The MOV writer uses `v210` or `2vuy` and preserves field order. Stereo signed 48 kHz PCM can be 16 or 32 bit. When preview uses 32-bit input for a 16-bit recording, use the high signed 16 bits. Readable no-input frames are saved and counted separately from valid or missing frames.
- DeckLink's VANC inspector gates line mapping on the device exposing all three driver properties and on the selected input type. The analog scan currently needs 525i59.94 NTSC. The scanner reads ancillary data first and can rotate mappings in temporary three-line sets, restoring the original configuration. Mapping changes the top rows of the raster and retains the negotiated frame size.
- Live WinUI scopes and spectrum use a 60 fps rendering target. Video scopes use each available progressive frame or field in source order. The spectrum uses overlapping audio windows paced by sample rate, so audio delivered in larger capture packets can still supply multiple updates.
- Monitoring has a phosphor luma waveform with broadcast legal-range guides, vectorscope with 75% color targets and skin-tone line, stereo spectrum with gradient fill and peak-hold trace, ballistic clip and phase bar meters, and filterable severity-coded recent events. The luma axis and raster share the same digital mapping for the 0, 7.5, and 100 IRE reference lines. Code labels follow the active capture scale (8-bit UYVY or 10-bit v210 for DeckLink). Spectrum frequency follows sample rate and its level floor follows the input PCM depth. Do not equate sample bit depth with maximum frequency. Recording writes received PCM in arrival order and records timestamp discrepancies, including resets, apparent gap and overlap lengths, and maximum cumulative offset. Video time resets use the nominal interval and a recovery baseline. Preserve decodable media on interruption, including single-track MOVs, and report missing tracks and estimated missing frames in QC.

## FireWire, DirectShow, and TS

- The i.LINK inspector reports the AV/C tape counter separately from TS segment time and broadcast time. Live HM-DHX2 preview verified the tape counter and program/PID display. An existing HM-DHX2 TS192 capture verified ARIB SIT event title and broadcast start. A continuous replay of HD and SD captures verified preview recovery and track replacement, and unit tests cover same-program PMT changes, clock jumps, SIT event changes, and DIT source changes. A physical same-tape discontinuity was not exercised in this validation.
- The live i.LINK preview re-probes FFmpeg after a TS pause or a stall while packets still arrive. Decoder recovery clears old video/audio state independently of capture and recording. Concatenated HM-DHX2 TS192 captures with different stream IDs reproduced the original failure and verified both 1080i-to-480i and reverse playback transitions.
- i.LINK preview keeps the decoded SD and HD raster through Bob-Weave. FFmpeg pads the AVI pipe to a fixed raster, and the receiver strips padding before monitoring. HM-DHX2 TS192 replay verified 720 × 480 and 1440 × 1080 at native size, and a synthetic MPEG-2 stream verified an in-stream SD-to-HD change. The preview HUD reports the source codec and decoded source pixel format before preview conversion. HM-DHX2 HD and SD replay reported MPEG-2 / yuv420p.
- The Windows app hosts DirectShow and i.LINK device selection in the right capture inspector. Both sources use the common transport controls, preview feed, decoded-frame scopes, audio meters and spectrum, and post-recording QC. Preview capabilities follow the selected format or the decoded stream. Original DirectShow samples and TS192 bytes are recorded independently of this monitoring path. Both Blackmagic WDM and VICTOR HM-DHX2 passed live WinUI preview, recording, and automatic QC handoff. The HM-DHX2 output matched received TS192 bytes exactly. Later HD broadcasts included malformed packets already present in the received stream.
- The desktop i.LINK source shares a single MSTape graph for FFmpeg preview and native TS192 recording. On VICTOR HM-DHX2, live preview decoding continued after recording stopped, and the recorded sample had no TS sync or continuity errors.
- FireWire / i.LINK is a CaptureRack device source. In Windows it uses MSTape through DirectShow. MSTape-specific discovery and format selection live in `CaptureRack.DirectShow/Windows/FireWire/MsTape/`. Shared COM bindings, media types, and callbacks are in `Windows/Interop/`.
- MSTape discovery enumerates the DirectShow video-input category, checks the `DeviceClassGUID`, and uses the device's unique ID when available. The negotiated media type decides downstream handling. TS output alone does not identify a FireWire device.
- `firewire list`, `probe`, `capture`, and `analyze` are available. Live capture currently accepts the native prefixed 192-byte MPEG-TS layout exposed to this probe. Preserve every received byte including the four-byte prefix. Offline analysis supports both 188-byte and 192-byte layouts. Do not generalize the live restriction to every MSTape driver or every other TS source.
- The shared TS writer leaves `.partial` on recording failure and protects existing outputs. The FireWire CLI writes a `.report.json` sidecar with byte counts, packet and timing diagnostics. TS transport analysis verifies packet structure and continuity, while decoded audio and video require separate checks.
- The DirectShow probe lists devices and pin formats, negotiates the requested formats, and counts incoming samples. Inspect advertised and negotiated media types separately. Optional capabilities include `IAMCrossbar` input routing. Uncompressed frames, compressed elementary streams, TS, DV, and waveform samples require different processing. Keep future MiniDV/MSDV and HDV behavior tied to verified device formats. Generic DirectShow preview and recording share a capture graph. Recording stages original samples to Matroska through a separate bounded queue. At stop, stream-copy compressed video to TS or try MOV and MP4, then keep MKV. Publish only candidates with matching stream formats and payload hashes. Failed capture retains .mkv.partial. DirectShow .recording.json tracks actual sample counts, driver timestamps and every container decision. WinUI and Probe can reopen MOV and MKV for full decoding and reconcile against the sidecar.

## RF and SDR diagnostics

- Keep the module name `SignalCapture` so it can cover RF and baseband signals such as CVBS. `Devices/Domesday/` contains DdD-specific diagnostics, `Devices/Sdr/RtlSdr/` contains RTL-SDR, and `Windows/` contains USB discovery and transport.
- DdD probe targets firmware through 3.2 and defaults to WinUSB. It recognizes legacy `1D50:603B` and protocol-v1 runtime `1209:2347`, inspects descriptors and stream endpoint, and checks protocol-v1 identity. USB protocol version alone does not establish the board revision. Streaming, MISRC capture, and live preview are future work.
- RTL-SDR diagnostics can list, probe, and configure a receiver, including frequency, sample rate, tuner gain, digital AGC, optional PPM, and supported VGA index. They use a matching native librtlsdr with WinUSB. RTL-SDR Blog V4 VGA needs the patched exports, plus a matching tuner and supported settings. The probe closes the diagnostic session without collecting I/Q.

## QC and shared decoder plans

- MOV QC decodes to the end and checks video frame and audio sample counts, field order, and PCM depth. It produces `.capture.json`, `.framemd5`, and `.mov.qctools.xml.gz`. Offline MOV checks are exposed in WinUI, Uno, and Probe. Use matching-architecture FFmpeg and FFprobe, with `cropdetect` for QCTools. Preserve recordings and prior reports across QC failures or retries.
- Uno runs TS analysis and exports JSON without FFmpeg or hardware. MOV QC in Uno uses the same QC engine and FFmpeg tools as the other entry points.
- MediaConch integration is deferred until an FFV1/MKV workflow exists. DV preview, macOS live capture, and standalone audio provider implementations are still planned.
- For future CVBS/RF preview, keep the reusable streaming decoder in the separate `vhs-decode-dotnet` repository. Start by replaying known CVBS samples at source rate. Share stateful sync and frame generation between its file preview and CaptureRack, then add VHS RF and live hardware. Verify release licensing before distributing a linked shared library. This integration is currently a design only.

- The WinUI source selector expands with the title bar and shows the full source summary in a native hover tooltip. DeckLink Studio 4K live preview verified the 1080i Top First HUD, and preview tests cover progressive and Bottom First metadata.

- The preview audio HUD reports DeckLink capture PCM or negotiated DirectShow audio, and uses the selected i.LINK input stream rather than downmixed monitor PCM. HM-DHX2 live preview and AAC/MP2 replay verified the source codec, sample rate, channel count and reported bitrate. Dual-audio replay verified stream selection.
