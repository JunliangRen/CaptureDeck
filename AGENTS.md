## Working conventions

- Target .NET 11. The production Windows app uses native WinUI 3 and XAML. Uno Desktop is a separate QC prototype with its own build entry point.
- Save text files with CRLF in the working tree. Preserve existing package names, namespaces, CLI commands, and settings compatibility through directory moves. Tests live under `test/`.
- For commits, follow the user's Git identity using the repository-local author name and locally configured email. Keep GitHub usernames, machine-specific paths, private sample data, and credentials out of tracked files. Push or publish when the user requests it.

## Platform boundaries and sample flow

- Windows x64 is the currently supported live path for DeckLink and MSTape. The native App and Probe also build for Windows ARM64 and can run offline QC there. Check every hardware/backend combination separately before claiming ARM64 support.
- Uno runs the offline workflow on Windows and is packaged for macOS ARM64 through its own workflow. A macOS live source needs a native capture backend and device validation. MSTape, DirectShow COM, and WinUSB are Windows implementations.
- `ICaptureBackend` and `CaptureBackendRegistry` provide backend identity and lookup. The generic backend contract has typed requests, progress, and results. The native app currently resolves DeckLink directly and the FireWire CLI calls its MSTape implementation directly.
- `CaptureSampleHandler` delivers a `CaptureSample` synchronously. Its span borrows bytes from the source for the duration of that callback. Copy into owned storage before queueing or returning. The current contract carries optional stream-relative start and end timestamps and a discontinuity flag. The stream format is negotiated separately. False rejects delivery.
- `DirectShowSink` uses this contract. `TsRecording` copies accepted samples into pooled storage under a 64 MiB queue budget. Keep recording byte-preserving and report overrun explicitly. For future monitoring, bound its queue independently and signal sample gaps to a stateful decoder.
- `ITransportController` in `TransportControl.cs` models supported commands and observed state separately from host capture. An accepted command and an observed state change are distinct outcomes. Device control providers for AV/C, JLIP, and other RS-232 protocols are planned.

- WinUI lets the operator choose the device, video input, audio input, input mode, media formats, and hardware analog input levels (Composite/S-Video 0.0/7.5 IRE setup, Component SMPTE/Betacam levels, Analog/XLR/RCA Pro/Consumer audio levels, and optional L/R hardware input gain scaling). The monitoring stage defaults to Studio Split with a draggable split divider (`SplitPreviewRatio`, double-click reset), video preview above switchable Luma waveform / RGB Parade (`Code` / `IRE` scale, severity-colored luma excursion readout) + Vectorscope/Spectrum/Events, a persistent ballistic stereo peak & phase meter with clickable L/R CLIP latch reset, and a collapsible/pinnable right inspector drawer (smooth slide-in/close + scrim fade, optional tape/reel filename label prefix with backend-accurate preview, and a reserved `TransportControlSlot` for future `ITransportController` UI). Preview-only display options (motion-adaptive Bob-Weave ×1 / ×2 or original preview, with progressive signals locked to original, display aspect override, BT.601/BT.709 matrix, safe-area & NTSC 480 crop guides, and non-blocking local speaker audio monitor toggled via `M`) never alter recorded media. Full-screen preview supports double-click, F11, Escape, hover/touch button fade, and an auto-hiding bottom mini control bar. Keyboard shortcuts also cover `Ctrl+1..5` (Focus / Split / Scopes / Spectrum / Events), `F5`, `F9`, and `Ctrl+I`. The single-row bottom bar holds preview and crimson record buttons, Composition-animated recording indicators (rotating reel, top stream sweep, 3-bar tally activity, breathing border), inline finalizing/container-remux progress pill, backend-driven live `TelemetryStrip` chips (including DirectShow unreadable/skipped, FireWire TS packets/bitrate/sync/CC/skipped, and DV frames/invalid/discontinuities/skipped), storage capacity bar, inline QC status/cancel, and status flyout. All animations respect Windows `UISettings.AnimationsEnabled`.
- Settings are loaded from `%LOCALAPPDATA%\CaptureRack\settings.json`. DeckLink, DirectShow, FireWire, TestSignal scenario, analog level, preview-only monitor, tape label, split ratio, scope mode/scale, and control selections are stored with backwards-compatible defaults; unplugged DirectShow/FireWire fallbacks preserve the saved device ID until explicitly changed and restore it on refresh when reconnected. Restore the last selections on launch and wait for the user to start preview. The settings page resolves the Windows display language on first launch or when migrating a legacy unset language, then persists one of English, Simplified Chinese, Traditional Chinese, and Japanese, alongside theme, default layout, preview defaults, and FFmpeg/FFprobe toolchain diagnostics. Keep the back header fixed and support Mouse Back and Alt+Left. Mouse wheel handling accepts `WM_MOUSEWHEEL`, `WM_POINTERWHEEL`, and a foreground-only raw mouse fallback across the Settings, QC Center, and right Inspector `ScrollView` panels while preserving open dropdowns across all backends and native scrolling.
- MOV recording starts from an active preview and an existing output directory. Auto detect requires a readable frame in the active preview mode before opening the writer. Readable no-input frames qualify and the UI labels the mode as a fallback. A detected mode change ends the current Auto clip before switching preview and is reported in QC. Names use local time, optional sanitized tape/reel label prefix (`RecordingFileNaming`), and format tokens, for example `CaptureRack_20261124_060236_633_10bit-Uncompressed_16bit-PCM.mov` or `Tape04_SideA_CaptureRack_20261124_060236_633_10bit-Uncompressed_16bit-PCM.mov`. Stopping recording finalizes the file and starts QC while preview continues. QC Center in CaptureRack.App supports MOV/MKV decode QC and offline raw DV + 188/192-byte MPEG-TS structural analysis (`TsFile.Analyze`, `DvFile.Analyze` + JSON export) with dedicated stream progress feedback, wrapping artifact actions (including folder/media open and DirectShow `.recording.json` access), drag-and-drop highlight, and a responsive clearable session QC history sidebar (`QcSessionHistory`).
- The SDK supplies 10-bit `v210` or 8-bit UYVY video. The MOV writer uses `v210` or `2vuy` and preserves field order. Stereo signed 48 kHz PCM can be 16 or 32 bit. When preview uses 32-bit input for a 16-bit recording, use the high signed 16 bits. Readable no-input frames are saved and counted separately from valid or missing frames.
- DeckLink's VANC inspector gates line mapping on the device exposing all three driver properties and on the selected input type. The analog scan currently needs 525i59.94 NTSC. The scanner reads ancillary data first and can rotate mappings in temporary three-line sets, restoring the original configuration. Mapping changes the top rows of the raster and retains the negotiated frame size.
- Live WinUI scopes and spectrum use a 60 fps rendering target. Video scopes use each available progressive frame or field in source order. The spectrum uses overlapping audio windows paced by sample rate, so audio delivered in larger capture packets can still supply multiple updates.
- Monitoring has a phosphor luma waveform with broadcast legal-range guides, vectorscope with 75% color targets and skin-tone line, stereo spectrum with gradient fill and peak-hold trace, ballistic clip and phase bar meters, and filterable severity-coded recent events. The luma axis and raster share the same digital mapping for the 0, 7.5, and 100 IRE reference lines. Code labels follow the active capture scale (8-bit UYVY or 10-bit v210 for DeckLink). Spectrum frequency follows sample rate and its level floor follows the input PCM depth. Do not equate sample bit depth with maximum frequency. Recording writes received PCM in arrival order and records timestamp discrepancies, including resets, apparent gap and overlap lengths, and maximum cumulative offset. Video time resets use the nominal interval and a recovery baseline. Preserve decodable media on interruption, including single-track MOVs, and report missing tracks and estimated missing frames in QC.

## FireWire, DirectShow, and TS

- DirectShow **Copy device diagnostics** collects the selected format, driver version, camera controls, and the latest explicit negotiation, sample, and preview evidence, including failure stage and HRESULT when available. Copying does not start capture. The inspection worker verified BRIO driver `1.0.85.0`, 14 camera controls, a successful YUY2 negotiation and 36 samples in a two-second test. A missing device returned a structured open-device failure.
- DirectShow camera controls query `IAMCameraControl`, `IAMVideoProcAmp` and known `IKsControl` properties. Idle access uses the inspection worker, and preview access runs on the active DirectShow graph thread. Camera controls are unavailable during recording. The Probe `directshow controls` command reports values, ranges, modes and the interface used. Logitech BRIO `046d:085e` verified read/write/readback and restoration for Brightness, LowLightCompensation and the vendor UVC FieldOfView control. - The DirectShow inspector groups driver formats into linked resolution, frame-rate, and color-space selectors. Downstream choices retain the previous value when the driver offers it for the new selection. Format details contains stream and exact driver-format variants, audio, scan metadata, and diagnostics. Live WinUI testing with Logitech BRIO verified the 3840 × 2160 selection switched to MJPG and negotiated at 30 fps.
- DirectShow scan metadata comes from the media type when present. For legacy `VIDEOINFOHEADER`, CaptureRack can use agreeing `VIDEOINFOHEADER2` flags for the same pin and sample layout, or the standard field order of the Blackmagic AVStream NTSC/PAL SD modes. Other formats with no conclusive metadata remain unknown. - The i.LINK inspector reports the AV/C tape counter separately from TS segment time and broadcast time. Live HM-DHX2 preview verified the tape counter and program/PID display. An existing HM-DHX2 TS192 capture verified ARIB SIT event title and broadcast start. - The live i.LINK preview re-probes FFmpeg after a TS pause or a stall while packets still arrive. Decoder recovery clears old video/audio state independently of capture and recording. Concatenated HM-DHX2 TS192 captures with different stream IDs reproduced the original failure and verified both 1080i-to-480i and reverse playback transitions.
- i.LINK preview keeps the decoded SD and HD raster through Bob-Weave. FFmpeg pads the AVI pipe to a fixed raster, and the receiver strips padding before monitoring. HM-DHX2 TS192 replay verified 720 × 480 and 1440 × 1080 at native size, and a synthetic MPEG-2 stream verified an in-stream SD-to-HD change. The preview HUD reports the source codec and decoded source pixel format before preview conversion. HM-DHX2 HD and SD replay reported MPEG-2 / yuv420p.
- The Windows app hosts DirectShow and i.LINK device selection in the right capture inspector. DV structural QC reads the VAUX profile, validates the DIF sequence layout, and reads embedded metadata. TS QC detects packet size from the content and accepts old `.ts192` files. - FireWire / i.LINK is a CaptureRack device source. In Windows it uses MSTape through DirectShow. MSTape-specific discovery and format selection live in `CaptureRack.DirectShow/Windows/FireWire/MsTape/`. Shared COM bindings, media types, and callbacks are in `Windows/Interop/`.

- The shared TS writer leaves `.partial` on recording failure and protects existing outputs. The FireWire CLI writes a `.report.json` sidecar with byte counts, packet and timing diagnostics. TS transport analysis verifies packet structure and continuity, while decoded audio and video require separate checks.

## RF and SDR diagnostics

- Keep the module name `SignalCapture` so it can cover RF and baseband signals such as CVBS. `Devices/Domesday/` contains DdD-specific diagnostics, `Devices/Sdr/RtlSdr/` contains RTL-SDR, and `Windows/` contains USB discovery and transport.
- DdD probe targets firmware through 3.2 and defaults to WinUSB. It recognizes legacy `1D50:603B` and protocol-v1 runtime `1209:2347`, inspects descriptors and stream endpoint, and checks protocol-v1 identity. USB protocol version alone does not establish the board revision. Streaming, MISRC capture, and live preview are future work.
- RTL-SDR diagnostics can list, probe, and configure a receiver, including frequency, sample rate, tuner gain, digital AGC, optional PPM, and supported VGA index. They use a matching native librtlsdr with WinUSB. RTL-SDR Blog V4 VGA needs the patched exports, plus a matching tuner and supported settings. The probe closes the diagnostic session without collecting I/Q.

## QC and shared decoder plans

- The desktop **Recording output** selection starts at Device original with legacy settings. DeckLink, DirectShow and the built-in test signal share the live FFmpeg writer in CaptureRack.Recording. FFV1 v3 uses slice CRC and FLAC level 8. H.264, H.265, AV1 and MPEG-2 expose bitrate and level, with explicit software deinterlacing for progressive-only profiles. Preview transformations remain independent. FireWire retains its native writer.
- Live encoder input uses timestamped Matroska over stdin. CaptureRack writes short output clusters and flushes checkpoints. Queue overrun or early encoder exit ends the recording, preserves the `.partial.mkv`, and records the reason when the checkpoint can be written. DeckLink reports software recording failures separately from preview failures. The recovery command validates element boundaries and available CRCs, copies the intact prefix into a separate file, and rebuilds keyframe cues without encoding.
- Local verification passed 195 Windows tests and 12 portable QC tests, plus an x64 App startup check. Regression tests cover legacy settings, encoding queue overrun, early encoder exit, truncated tails, and same-length CRC damage. Physical power-loss recovery and full-length live encoder throughput remain unverified.
- The live checkpoint and final encoding report include source timestamp gaps, queue peaks and rejections, packets or frames submitted to FFmpeg, peak encoder input and media write and flush durations, and the last complete Cluster start time. Full QC decode backfills the output frame count. Local verification passed 199 Windows tests and 12 portable QC tests. Coverage includes simulated DeckLink and DirectShow gaps, a blocked encoder input, accurate queue peaks under concurrent enqueue and dequeue, delayed and failed media writes, the recoverable Cluster boundary, and preservation of completed decode counts across successful, failed, and cancelled QC reruns.
- MOV QC decodes to the end and checks video frame and audio sample counts, field order, and PCM depth. It produces `.capture.json`, `.framemd5`, and `.mov.qctools.xml.gz`. Offline MOV checks are exposed in WinUI, Uno, and Probe. Use matching-architecture FFmpeg and FFprobe, with `cropdetect` for QCTools. Preserve recordings and prior reports across QC failures or retries.
- Uno runs TS analysis and exports JSON without FFmpeg or hardware. MOV QC in Uno uses the same QC engine and FFmpeg tools as the other entry points.
- MediaConch policy checks remain a follow-up to the FFV1/MKV workflow. macOS live capture and standalone audio provider implementations are still planned.
- For future CVBS/RF preview, keep the reusable streaming decoder in the separate `vhs-decode-dotnet` repository. Start by replaying known CVBS samples at source rate. Share stateful sync and frame generation between its file preview and CaptureRack, then add VHS RF and live hardware. Verify release licensing before distributing a linked shared library. This integration is currently a design only.

- The preview audio HUD reports DeckLink capture PCM or negotiated DirectShow audio, and uses the selected i.LINK input stream rather than downmixed monitor PCM.
