# CaptureRack agent memory

This is the repository handoff for coding agents. Start with the current Git status, the owning source, and [README.md](README.md). This file records architecture decisions and the last verified state. Update the relevant section when a change ships or its verification status changes.

## Working conventions

- Target .NET 11. The production Windows app uses native WinUI 3 and XAML. Uno Desktop is a separate QC prototype with its own build entry point.
- Save text files with CRLF in the working tree. Preserve existing package names, namespaces, CLI commands, and settings compatibility through directory moves. Tests live under `test/`.
- For commits, follow the user's Git identity using the repository-local author name and locally configured email. Keep GitHub usernames, machine-specific paths, private sample data, and credentials out of tracked files. Push or publish when the user requests it.

## Platform boundaries and sample flow

- Windows x64 is the currently supported live path for DeckLink and MSTape. The native App and Probe also build for Windows ARM64 and can run offline QC there. Check every hardware/backend combination separately before claiming ARM64 support.
- Uno runs the offline workflow on Windows and is packaged for macOS ARM64 through its own workflow. A macOS live source needs a native capture backend and device validation. MSTape, DirectShow COM, and WinUSB are Windows implementations.
- `ICaptureBackend` and `CaptureBackendRegistry` provide backend identity and lookup. The generic backend contract has typed requests, progress, and results. The native app currently resolves DeckLink directly and the FireWire CLI calls its MSTape implementation directly.
- `CaptureSampleHandler` delivers a `CaptureSample` synchronously. Its span borrows bytes from the source for the duration of that callback. Copy into owned storage before queueing or returning. The current contract carries optional stream-relative start and end timestamps and a discontinuity flag. The stream format is negotiated separately. False rejects delivery.
- `DirectShowSink` uses this contract. `TsRecording` copies accepted samples into pooled storage under a 64 MiB queue budget. Keep recording byte-preserving and report overrun explicitly. For future monitoring, bound its queue independently and signal sample gaps to a stateful decoder.
- `ITransportController` in `TransportControl.cs` models supported commands and observed state separately from host capture. An accepted command and an observed state change are distinct outcomes. Device control providers for AV/C, JLIP, and other RS-232 protocols are planned.

- MOV recording starts from an active preview and an existing output directory. Auto detect requires a readable frame in the active preview mode before opening the writer. Names use local time, optional sanitized tape/reel label prefix (`RecordingFileNaming`), and format tokens, for example `CaptureRack_20261124_060236_633_10bit-Uncompressed_16bit-PCM.mov` or `Tape04_SideA_CaptureRack_20261124_060236_633_10bit-Uncompressed_16bit-PCM.mov`. - The SDK supplies 10-bit `v210` or 8-bit UYVY video. The MOV writer uses `v210` or `2vuy` and preserves field order. Stereo signed 48 kHz PCM can be 16 or 32 bit. When preview uses 32-bit input for a 16-bit recording, use the high signed 16 bits. Readable no-input frames are saved and counted separately from valid or missing frames.
- DeckLink's VANC inspector gates line mapping on the device exposing all three driver properties and on the selected input type. The analog scan currently needs 525i59.94 NTSC. The scanner reads ancillary data first and can rotate mappings in temporary three-line sets, restoring the original configuration. Mapping changes the top rows of the raster and retains the negotiated frame size.
- Live WinUI scopes and spectrum use a 60 fps rendering target. Video scopes use each available progressive frame or field in source order. The spectrum uses overlapping audio windows paced by sample rate, so audio delivered in larger capture packets can still supply multiple updates.
- Monitoring has a phosphor luma waveform with broadcast legal-range guides, vectorscope with 75% color targets and skin-tone line, stereo spectrum with gradient fill and peak-hold trace, ballistic clip and phase bar meters, and filterable severity-coded recent events. The luma axis and raster share the same digital mapping for the 0, 7.5, and 100 IRE reference lines. Code labels follow the active capture scale (8-bit UYVY or 10-bit v210 for DeckLink). Spectrum frequency follows sample rate and its level floor follows the input PCM depth. Do not equate sample bit depth with maximum frequency. Recording writes received PCM in arrival order and records timestamp discrepancies, including resets, apparent gap and overlap lengths, and maximum cumulative offset. Video time resets use the nominal interval and a recovery baseline. Preserve decodable media on interruption, including single-track MOVs, and report missing tracks and estimated missing frames in QC.

## QC and shared decoder plans

- The desktop **Recording output** selection starts at Device original with legacy settings. DeckLink, DirectShow and the built-in test signal share the live FFmpeg writer in CaptureRack.Recording. FFV1 v3 uses slice CRC and FLAC level 8. H.264, H.265, AV1 and MPEG-2 expose bitrate and level, with explicit software deinterlacing for progressive-only profiles. Preview transformations remain independent. FireWire retains its native writer.
- Live encoder input uses timestamped Matroska over stdin. CaptureRack writes short output clusters and flushes checkpoints. Queue overrun or early encoder exit ends the recording, preserves the `.partial.mkv`, and records the reason when the checkpoint can be written. DeckLink reports software recording failures separately from preview failures. The recovery command validates element boundaries and available CRCs, copies the intact prefix into a separate file, and rebuilds keyframe cues without encoding.
- Local verification passed 195 Windows tests and 12 portable QC tests, plus an x64 App startup check. Regression tests cover legacy settings, encoding queue overrun, early encoder exit, truncated tails, and same-length CRC damage. Physical power-loss recovery and full-length live encoder throughput remain unverified.
- The live checkpoint and final encoding report include source timestamp gaps, queue peaks and rejections, packets or frames submitted to FFmpeg, peak encoder input and media write and flush durations, and the last complete Cluster start time. Full QC decode backfills the output frame count. Local verification passed 199 Windows tests and 12 portable QC tests. Coverage includes simulated DeckLink and DirectShow gaps, a blocked encoder input, accurate queue peaks under concurrent enqueue and dequeue, delayed and failed media writes, the recoverable Cluster boundary, and preservation of completed decode counts across successful, failed, and cancelled QC reruns.
- Release v0.4.0 was built from 478d11d. The Windows x64 and ARM64 jobs and macOS ARM64 job passed. The three published packages were checked for version and architecture, and the GitHub asset digests matched the local SHA-256 hashes.
- MOV QC decodes to the end and checks video frame and audio sample counts, field order, and PCM depth. It produces `.capture.json`, `.framemd5`, and `.mov.qctools.xml.gz`. Offline MOV checks are exposed in WinUI, Uno, and Probe. Use matching-architecture FFmpeg and FFprobe, with `cropdetect` for QCTools. Preserve recordings and prior reports across QC failures or retries.
- Uno runs TS analysis and exports JSON without FFmpeg or hardware. MOV QC in Uno uses the same QC engine and FFmpeg tools as the other entry points.
- MediaConch policy checks remain a follow-up to the FFV1/MKV workflow. macOS live capture and standalone audio provider implementations are still planned.
- For future CVBS/RF preview, keep the reusable streaming decoder in the separate `vhs-decode-dotnet` repository. Start by replaying known CVBS samples at source rate. Share stateful sync and frame generation between its file preview and CaptureRack, then add VHS RF and live hardware. Verify release licensing before distributing a linked shared library.
